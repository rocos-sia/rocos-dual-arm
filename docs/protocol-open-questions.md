# 首版协议待决策项

本文整理接口审阅中的待定事项，是后续讨论清单，不代表已经实现或冻结的协议。原始 v0.1 讨论稿见 [双臂 DDS 接口设计](dual_arm_dds_interface_design.md)。

| 项目 | 需要确定的行为 |
|---|---|
| 时间契约 | 各时间字段所属时钟；主机到控制器的映射、误差阈值；最晚接收、最晚启动和运行超时的区别 |
| 会话与租约 | 控制器启动标识、客户端会话、授权代号；请求/授予/续约/撤销方向；命令如何绑定当前授权 |
| 序号 | 按发布源和逻辑流定义作用域；不能依赖多个 Topic 的全局到达顺序 |
| 命令恢复 | 命令 ID 去重、同 ID 不同内容的拒绝、结果查询、结果保留期限与重启后的未知状态 |
| 双臂同步 | 同步启动、同步到达或路径协作的支持范围；资源预留和组提交完成后才发 ACCEPTED |
| 轨迹更新 | 顺序追加与滚动覆盖分开定义；可跳过版本的条件；不可修改窗口及拼接连续性 |
| 缓冲反馈 | 剩余执行时间、覆盖截止时间、已接受片段以及缓冲不足阈值 |
| 停止与取消 | 高优先级处理机会；目标范围；待执行队列清理；租约失效后的任务处置 |
| QoS | 双端配置、History 类型、资源上限、发布阻塞时间、超时及队列满策略 |
| 故障状态 | 当前故障快照与事件历史分离；明确跨重启保存要求 |
| 设备能力 | 关节顺序、自由度、单位、坐标系、工具与标定版本；支持的控制模式 |
| rocos-app 适配 | 核对 Robot、Executor、Hardware 的源码、线程、生命周期和双臂资源归属 |
| 协议演进 | 固定首版消息集合，确定 IDL 类型演进策略以及版本兼容性验证方式 |
| 部署环境 | 操作系统、工具链、Fast DDS/生成器版本、网卡与发现方式、单进程或多控制进程 |

## 原始字段待修订

- `MODE_CARTESIAN_TWIST` 缺少对应的线速度和角速度载荷。
- `MODE_TRAJECTORY` 需要明确与 `ServoChunk` 的关系。
- 速度、加速度、跃度限制需要明确单位及逐关节/平移/旋转的表达。
- `active_command_sequence` 与公共序号位宽不同；状态还需明确活动命令关联。
- `FaultEvent` 需要明确命令和执行组关联字段。
- `time_from_start_ns` 与 `point_period_ns` 需要权威字段或一致性规则。
- DDS 接收线程与实时循环隔离应放在第一阶段。

## 首轮验收场景

1. 旧租约的命令在新租约生效后到达，确定性拒绝。
2. 动作完成但完成 ACK 未被客户端获得，客户端可查询结果且不会重复执行。
3. 滚动轨迹缺失中间版本，根据覆盖区间和更新模式处理，不只根据序号决定停机。
4. 任一机械臂资源不足时，执行组整体拒绝，两侧均不启动。
5. 普通队列满时，停止请求仍有确定的处理路径。
6. 控制器重启后，旧会话指令不能自动恢复执行。
