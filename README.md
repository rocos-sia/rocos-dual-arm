# ROCOS 双臂运动控制

基于 Fast DDS 的双臂分布式运动控制项目，面向控制器、策略、视觉、夹爪和技能模块的多人协作开发。

当前状态：仓库初始化与架构讨论阶段。已归档原始接口讨论稿，尚未冻结 IDL、实现通信 SDK 或接入真实硬件。

## 架构边界

```text
策略 / 视觉 / 技能 / 调试客户端
             ↓
机器人业务 SDK（后续实现）
             ↓
统一接口协议 + 公共通信 SDK
             ↓ Fast DDS
DDS Gateway → 双臂协调器 → 本地运动控制器 → Hardware
```

- Fast DDS 负责进程间通信；公共通信 SDK 统一实体生命周期、类型化收发、QoS 配置和诊断。
- 控制器负责控制权仲裁、命令校验、轨迹缓存、双臂协调和异常处理。
- 本地实时循环负责插补与伺服，不依赖网络维持控制周期，不直接执行 DDS 收发或日志输出。
- 初期通过适配器对接 rocos-app 的 `Motion → Controller → Hardware` 链路；实际类和线程映射需要源码验证。

## 目录

| 目录 | 职责 |
|---|---|
| `interfaces/` | IDL、Topic 定义和消息行为契约 |
| `comm/` | Fast DDS 公共通信 SDK |
| `controller/` | DDS Gateway、命令管理和双臂协调 |
| `sdk/` | 面向策略和技能开发者的机器人业务 API |
| `examples/` | 发布订阅、模拟控制器和端到端联调示例 |
| `tests/` | 协议、模拟器与故障注入测试 |
| `docs/` | 原始设计、架构边界和待决策项 |

各实现目录目前仅包含职责说明，没有可构建的程序。

## 开始协作

1. 阅读 [原始接口讨论稿](docs/dual_arm_dds_interface_design.md)。该文件保留 v0.1 原文，不能直接作为冻结后的执行契约。
2. 阅读 [首版待决策项](docs/protocol-open-questions.md)，先确定时间、租约和轨迹更新语义。
3. 按 [协作约定](CONTRIBUTING.md) 提交接口变更，保证发布端、订阅端使用同一版本的协议。
4. 首先完成模拟环境中的命令、状态、确认闭环，再逐步接入硬件。
